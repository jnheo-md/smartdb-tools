SmartDB Tools

Command-line interface and MCP server for the SmartDB Stroke Registry

Access clinical data from the SmartDB multi-center stroke registry through a terminal CLI or AI-assisted IDE integration. Supports schema exploration, patient data queries, outcome analysis, and data export across participating hospitals. Requires an authorized registry account.

Overview

Registry Access

Query patient data, schemas, and clinical variables from the SmartDB database through a structured API. Browse hospitals, tables, and variable definitions across the registry.

Data Export

Export filtered cohorts to XLSX for analysis in R, Python, SAS, or other statistical software. Supports variable selection and filter conditions.

MCP Integration

Integrate with AI-assisted development environments via the Model Context Protocol. Use natural language to query the registry through compatible tools.

For first-time users

Start here if this is a new computer

SmartDB Tools can be used by itself in a terminal, or through an AI coding assistant such as Claude Code or Codex. You do not need all options. Pick one path, install the prerequisites, then run the SmartDB installer.

Recommended

Terminal only

Best for direct queries and exports. This is the simplest setup and does not require an AI assistant.

  • Install Python 3.10 or newer
  • Install Git if it is not already installed
  • Run the SmartDB installer
  • Log in with your SmartDB account
AI + MCP

Claude Code

Best when you want to ask natural-language questions and let the MCP server expose safe SmartDB tools.

  • Install Node.js 18 or newer
  • Install Claude Code
  • Run the SmartDB installer, which configures MCP
AI + CLI

Codex

Best when you want an AI coding agent to run SmartDB CLI commands and follow the repository instructions.

  • Install Node.js and Codex CLI
  • Install SmartDB Tools
  • Open this repository in Codex
1

Install Python

SmartDB Tools uses Python internally. Install Python 3.10 or newer from python.org. The installer also needs Git; install it from git-scm.com if your computer does not already have it. Then open Terminal or PowerShell and confirm:

python3 --version git --version

On Windows, use python --version if python3 is not recognized.

2

Optional: install an AI coding assistant

Skip this step if you only want terminal commands. For Claude Code or Codex, install Node.js first from nodejs.org, then choose one assistant:

Claude Code

npm install -g @anthropic-ai/claude-code claude --version

Official guide: Claude Code quickstart.

Codex CLI

npm install -g @openai/codex codex --version

Official guide: OpenAI Codex CLI setup.

3

Install SmartDB Tools

Run the installer for your operating system. The installer creates a private Python environment in ~/.smartdb, installs the CLI, and offers to configure MCP where supported.

If login fails because of a mistyped password, SmartDB gives you three attempts before stopping. After installation, use smartdb ai setup --tools auto to reconfigure Claude Code, Claude Desktop, Codex, Cursor, Windsurf, or Pi Coding Agent.

4

Keep SmartDB Updated

SmartDB checks once per day in interactive terminals and recommends an upgrade when a newer CLI is available. The check is cached and does not stop commands if the network is offline.

smartdb update smartdb update --check

To disable reminders, run smartdb config set-update-check off. Re-enable with smartdb config set-update-check on.

Installation

Prerequisites checklist

  • Required: Python 3.10 or later
  • Required: Git, so the installer can download the project source
  • Required: macOS, Linux, or Windows 10/11
  • Required: authorized SmartDB registry account
  • Optional for Claude Code/Codex: Node.js 18 or later and an authenticated AI assistant account

Quick Install

Run the installer script to set up SmartDB Tools and its dependencies:

macOS / Linux:

curl -fsSL https://raw.githubusercontent.com/jnheo-md/smartdb-tools/master/install.sh | bash

Windows (PowerShell):

irm https://raw.githubusercontent.com/jnheo-md/smartdb-tools/master/install.ps1 | iex

Post-Install

Authenticate with your registry credentials and verify access:

smartdb login smartdb whoami smartdb ai setup --tools auto

Usage

Schema Exploration

Browse hospitals, tables, and variables. Search across clinical data points with fuzzy matching.

smartdb schema hospitals smartdb schema search YSU "blood pressure" smartdb schema variable YSU admission_NIH_day_0

Patient Data Queries

Query patient data with automatic table joins. Filter by any variable with support for complex conditions.

smartdb query data YSU \ --vars "pt_sex,pt_age,admission_NIH_day_0" \ --filters '[{"variable":"Thr_mechanical","operator":"=","value":"1"}]'

Follow-up Outcomes

Retrieve mRS outcomes with automatic death imputation from the cohort table.

smartdb query followup YSU --period 3m smartdb query followup YSU --period 12m --limit 20

Clot Composition Data

Access thrombus histology data from the ARIA study, including platelet, fibrin, RBC, and neutrophil composition.

smartdb clot patients YSU smartdb clot composition YSU YSU001

Data Export

Export filtered datasets to XLSX for downstream analysis.

smartdb export xlsx YSU --vars "pt_sex,pt_age,admission_NIH_day_0" smartdb export followup YSU -p 3m -v "pt_sex,pt_age"

AI Agent Setup

MCP-based tools (Claude, Codex, Cursor, Windsurf, Pi Coding Agent): The installer can auto-configure the MCP server with built-in safety rules, layout-first workflows, and dedicated tools for NIHSS and mRS outcomes. Rerun setup any time with:

smartdb ai setup --tools auto

Windows Claude Desktop note: Microsoft Store/MSIX installs may read MCP settings from %LOCALAPPDATA%\Packages\...\LocalCache\Roaming\Claude instead of the standard %APPDATA%\Claude folder. SmartDB updates both locations when detected; restart Claude Desktop after setup.

CLI-based tools (Copilot, Aider, and other shell-capable agents): Install the CLI, then the AI agent can run smartdb guide to learn the domain rules and use any smartdb command. An AGENTS.md file in the repository provides structured instructions for AI agents.

For the full cross-platform AI reference, see SMARTDB_AI_GUIDE.md.

Optional per-user setup

Preprocessing Preferences

Users can keep personal preferences for how exported data should be cleaned, deduplicated, or formatted. These preferences are local and opt-in, so default SmartDB exports are unchanged for everyone else.

Free-text memory

Store plain-language notes about how you usually want data processed. This is advisory only and cannot directly modify data.

smartdb preprocess init --scope user smartdb preprocess memory add "For EVT exports, keep an audit trail."

Deterministic profiles

Actual processing rules live in preprocess.toml. Profiles can be listed, explained, and validated before MCP or a user applies them.

smartdb preprocess list-profiles smartdb preprocess validate

Reference sample: Pf. Nam preferences

A sample profile file is included at examples/preprocess/pf_nam_preprocess.toml. It contains preprocessing preferences made by Pf. Nam and can be inspected, copied, or passed explicitly.

smartdb preprocess list-profiles --config examples/preprocess/pf_nam_preprocess.toml smartdb preprocess explain pf_nam_evt --config examples/preprocess/pf_nam_preprocess.toml smartdb preprocess validate pf_nam_evt --config examples/preprocess/pf_nam_preprocess.toml

MCP should read these preferences, summarize intended actions, validate source fields and saved-value encodings, then ask for confirmation before applying any profile.

Safety rules

  • Free-text memory is advisory only; actual rules must be deterministic TOML profiles.
  • Do not store patient identifiers or clinical values in memory files.
  • SmartDB safety rules still apply: use dedicated NIHSS and follow-up tools instead of unsafe post-processing shortcuts.

Data Security

SmartDB Tools does not store or cache patient data locally. All queries are executed through an authenticated API layer that enforces institutional access controls. No database credentials are transmitted to or stored on the client.

  • HTTPS-only API access — all data transmission is encrypted in transit. No direct database connections.
  • Role-based authorization — server-side permission enforcement limits data access to the user's authorized scope and institutional affiliation.
  • Encrypted session storage — JWT tokens are stored with restricted file permissions (0600 on macOS/Linux) and expire automatically.

See SECURITY.md for the full security policy.
